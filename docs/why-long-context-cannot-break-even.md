# RAISE 收益判据分析：为什么长上下文推测解码在数学上无法翻正

> 数据来源：`results_raise/raise_calib_fp16.json`（A100，10 剖面，每剖面 15 次重复取中位）
> 全部数字为实测，推导过程可复算。**测量条件为共享 GPU（存在同事进程竞争），见 §6 局限。**

---

## 1. 判据推导

固定 k 推测解码，每轮成本与产出：

```
基线：C = k·t_d + t_b + p·t_b     （含失配后重做一次目标前向的冗余项 = W1）
RAISE：C = k·t_d + t_b             （M1 增量回退消除该项）
每轮产出：μ（平均接受 token 数）
```

与自回归（单 token 成本 t_1）竞速：`C/μ < t_1`

记 **γ = t_d/t_1**（草稿相对成本）、**β = t_b/t_1**（验证块相对成本）：

```
基线翻正条件：μ > kγ + (1+p)β
RAISE 翻正条件：μ > kγ + β
```

---

## 2. 实测 γ / β（关键发现：γ ≈ 0.80）

| 剖面 | 上下文长度 | t1 (ms) | td (ms) | tb (ms) | **γ** | β | 门槛 μ*(RAISE) |
|---|---|---|---|---|---|---|---|
| multi_news | 835 | 19.323 | 15.623 | 21.789 | 0.8085 | 1.1276 | **4.362** |
| lcc | 2399 | 19.204 | 15.522 | 22.372 | 0.8083 | 1.1650 | **4.398** |
| multifieldqa | 2518 | 19.280 | 15.507 | 22.625 | 0.8043 | 1.1734 | **4.391** |
| qasper | 3584 | 19.175 | 15.381 | 25.259 | 0.8021 | 1.3173 | **4.526** |
| gov_report | 8192 | 19.338 | 15.473 | 36.254 | 0.8001 | 1.8747 | **5.075** |
| narrativeqa | 8192 | 19.353 | 15.466 | 36.286 | 0.7992 | 1.8750 | **5.072** |
| qmsum | 8192 | 19.355 | 15.540 | 36.255 | 0.8029 | 1.8731 | **5.085** |
| samsum-long | 8192 | 19.311 | 15.474 | 36.338 | 0.8013 | 1.8817 | **5.087** |
| repobench-p | 8192 | 19.301 | 15.420 | 36.223 | 0.7989 | 1.8767 | **5.072** |
| hotpotqa-long | 8192 | 19.132 | 15.312 | 36.504 | 0.8004 | 1.9080 | **5.109** |

**两个直接读数**：
1. **γ ≈ 0.80 全剖面稳定**（0.799–0.809）。即 0.5B 草稿模型的单 token 前向耗时是 7B 目标模型的 **80%**——参数量差 14 倍，耗时只差 1.25 倍。
2. **β 随上下文线性增长**：ctx 835 → β=1.13；ctx 8192 → β=1.88。验证块（k+1=5 token）成本约等于 1.1–1.9 个单 token 前向。

---

## 3. 不可行性结论（本文的理论核心）

### 3.1 长上下文下，k=4 在数学上不可能翻正

即使接受率达到 **100%**（每轮接受 k+1 = 5 个 token，这是单轮产出的**上界**）：

```
RAISE 理论最大加速比 = (k+1) / (kγ + β) = 5 / 5.081 = 0.984×
基线 理论最大加速比 = (k+1) / (kγ + 2β) = 5 / 6.955 = 0.719×      （p=1 最坏）
```

> **μ* = 5.081 > k+1 = 5** → 门槛超过单轮最大产出，**A100 / ctx=8192 / k=4 下不可翻正**。
> 这不是"草稿质量不够"，而是**收益条件本身不成立**——换更强的 drafter 也救不了 k=4。

### 3.2 门槛的上下文依赖性（同一条判据解释了正负反转）

| 上下文 | RAISE 理论上限 | 是否可翻正 |
|---|---|---|
| ctx ≈ 835 | **1.146×** | ✅ 可以 |
| ctx ≈ 8192 | **0.984×** | ❌ 不可以 |

**在短上下文（β 小）时推测解码有利，长上下文（β 大）时不利**——这条判据一次性解释了为什么 4090 上得到正收益、A100 长上下文全盘负加速，无需引入任何特例假设。

### 3.3 增大 k 的理论收益与现实的落差

| k | 理论最大加速比（含 100% 接受） | 实际需要的最低接受率 |
|---|---|---|
| 4 | 0.984× | 不可能 |
| 8 | **1.086×** | 92% |
| 16 | 1.156× | 74% |
| 32 | 1.199× | 58% |

理论上 **k 越大越有利**（因 γ<1，草稿比目标便宜）。但实测 k=2/4/6 的加速比几乎不变（0.48–0.52×）——**接受率随 k 崩塌**，实际 μ 不增长。所以"简单加大 k"无效，要的是**提高单位草稿的命中率**。

---

## 4. 要翻正需要什么：γ 必须压到 0.25 以下

当前实测接受长度 μ ≈ 2.82（RAISE-fixed4），翻正条件 `μ > kγ + β` 反解 γ：

```
γ < (μ - β) / k = (2.82 - 1.874) / 4 = 0.237
```

| 若 γ 降到 | 门槛 μ* | 对比实测 μ=2.82 | 结论 |
|---|---|---|---|
| 0.80（现状） | 5.08 | 差 80% | ❌ |
| 0.40 | 3.47 | 差 23% | ❌ |
| **0.237** | **2.82** | 临界 | ⚠️ |
| 0.15 | 2.47 | 富余 14% | ✅ 约 1.14× |

> **结论：唯一现实的翻正路径是把 γ 从 0.80 压到 0.24 以下**，即让草稿侧**不再随上下文线性增长**。这正是 LongSpec（常数 KV + 滑动窗口自注意力，公开报告最高 3.26×）与 OWL（last-token LSTM 条件草稿，接受长度较 EAGLE-3 高约 5×）走的路——不是换概念，而是**动 γ 的分子**。

---

## 5. 为什么 γ 会塌陷到 0.8：机理

长上下文解码是 **memory-bound**：每生成 1 个 token 都要读完整 KV cache 与全部权重。
草稿与目标模型的 KV cache 单 token 开销（Qwen2.5-0.5B vs 7B，fp16）：

| 模型 | 层数 | KV 头数 | head_dim | 每 token KV 字节 |
|---|---|---|---|---|
| Qwen2.5-0.5B | 24 | 2 | 64 | 12,288 |
| Qwen2.5-7B | 28 | 4 | 128 | 57,344 |

比值约 **4.7×**。若 γ 纯由 KV 带宽决定，应约为 0.21；**实测 0.80，远高于此**——说明存在非带宽因素（kernel 启动开销、小 batch 下的低占用率、以及共享 GPU 的资源竞争）。这也意味着 **γ 有可观的工程压缩空间**，与 §4 的目标（γ<0.24）方向一致。

---

## 6. 局限（必须写进论文的诚实声明）

1. **测量在共享 GPU 上进行**：实测期间有同事进程长期占用约 33 GB 显存、GPU 利用率 57%–100%。小模型（0.5B）单次前向绝对时间短，受调度与竞争延迟的影响**相对更大**，因此 **γ=0.80 可能被高估**。
   → **独占 GPU 复测 γ 是下一步必须先做的事**（一次标定仅需 ~30 秒）。
2. **单轮产出上界按 k+1 计算**，未计入 EOS 提前终止与树形草稿的可能扩展。
3. 判据基于固定 k；自适应 k（M2）的门槛形式不同，但结论方向一致。

---

## 7. 对论文的意义（回应"缺少实质性技术改进"）

这套判据把此前只能当"现象"描述的三件事，变成了**一个可复算的定量框架**：

| 此前 | 现在 |
|---|---|
| "长上下文推测解码会变慢"（现象，且 OWL 已报告） | 收益条件 `μ > kγ + (1+p)β`，实测 γ=0.80、β=1.87 → 门槛 5.08 **> 单轮上界 5** |
| "4090 与 A100 结论相反"（无法解释） | 门槛的上下文/硬件依赖性，同一公式预测两处结果 |
| "调度层优化不够"（主观判断） | RAISE 精确降低 pβ 项：门槛 6.20 → 5.08（−18%），但仍越界；量化出翻正所需 **γ<0.24** |

**这就是"计算机技术层面的实质性改进"**：不是又调了一个 k，而是给出了**收益条件的解析判据 + 实测标定 + 不可行性证明 + 工程目标（γ 阈值）**。
